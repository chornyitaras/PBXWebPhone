PBXWebPhone

Static WebRTC phone for Vicidial.

PBXWebPhone is a lightweight browser softphone built around SIP.js. The current project runs as static HTML and JavaScript, with an optional index.php compatibility shim for older integrations.

This page is designed to live inside docs/ so it can be published directly with GitHub Pages.

Getting Started

  1. Clone this repository into your Vicidial web directory.
  2. Serve the project over HTTP or HTTPS. A secure connection is required for WebRTC in normal browser setups.
  3. Configure Asterisk, Apache, Vicidial, and firewall access for the WebSocket endpoint.
  4. Open index.html for the phone or test.html for the local test harness.
Existing systems that still point to index.php can continue using that path. The compatibility layer now forwards them to the static app.

Deployment Notes

  • The application itself lives in the repository root.
  • This docs/ folder is documentation-only and is safe to publish through GitHub Pages.
  • For GitHub Pages, set the Pages source to the repository branch and the /docs folder.
  • If you publish the full app elsewhere, keep the WebSocket server reachable from the browser.

Query Parameters

The phone bootstraps itself entirely from query parameters. Values are expected to be base64-encoded.

phone_login

Agent or extension login used for SIP authorization and display name.

phone_pass

Password used when registering the SIP user.

options

Encoded option string. The current app extracts the WebSocket URL from a WEBSOCKETURL... token inside this field.

server_ip

Accepted for compatibility. The current static boot flow preserves it in the config object.

Sample Launch URL

index.html?phone_login=BASE64_LOGIN&phone_pass=BASE64_PASS&options=BASE64_OPTIONS

The local test page constructs this URL for you, including the WebSocket option string expected by the app.

Useful project files

  • index.html for the static phone UI
  • scripts/bootstrap.js for decoding incoming query parameters
  • scripts/phone.js for SIP registration, call lifecycle, keypad, and mute behavior
  • test.html for manual browser-side testing

What the UI Looks Like

The current static interface keeps the webphone intentionally small and focused: connection state, call state, mute, and a keypad overlay for DTMF input.
